// **`match` is Mojo's pattern-matching statement**, a keyword since 1.2, with
// `__match` kept as its deprecated spelling (`TokenKinds.def:137,171` at
// `mojo/v1.2.0`). It is not Python's `match`. The production is the comment
// above `parseMatchStmt` (`ParserStmts.cpp:1693-1695`), and the two indentation
// styles are named at `1766-1767`.
//
// The first two cases pin those styles: cases level with the `match` (Mojo
// style; 133 statements in the 1.2 sources, nearly all in tests) and cases
// indented beneath it (Python style; 316 statements, and what the library
// writes). The third pins "the `if` after a pattern is a guard": Mojo stops the
// pattern at `if`, and this grammar does it with the `prec(PREC.conditional + 1)`
// on `_case_pattern`.
//
// The fourth is the negative one: a keyword still parses where only a name
// fits. Mojo rejects `def __match():` with a diagnostic ("cannot be used as a
// function name in this context", `decls/keyword_fn_names.mojo:252-253`), but
// that is a check after parsing, and the grammar should not turn it into an
// ERROR. It holds because of the `word` token: a keyword that is not valid in
// that state falls back to an identifier. **Every new keyword wants a case like
// this**, or "this name can no longer be used" regressions go unseen.
//
// The rest are the 1.2 additions: bare `match`, `comptime match`, comma lists
// for the subject and the pattern, `*rest`, `as` as a pattern operator, and the
// prefix `==`.
//
// Warning: **`tree-sitter test -u` deletes this header**, and not only in the
// file `--file-name` names. Run `-u` first and write the comments after.
